# 诊断日志与问题反馈

[English](diagnostic-logging.en.md)

从 0.2.3-beta.1 起，`traceId`、`parentTrace`、`origin`、`jobId` 关联插件操作、窗口回调和布局任务。来源编号：1 标签命令、2 布局执行、3 刷新、4 原生窗口消息、5 绘制、6 几何应用、7 恢复；父编号表示观测到的调用上下文，不能单独证明因果。外部激活仍可能无法区分来自用户、Office 或 Windows。

窗口 API 编号：1 活动窗口、2 前台窗口、3 位置、4 显示状态、5 COM 激活、6 窗口放置。记录调用前后状态与错误码，API 接受不等于视觉正确。布局取消原因：1 替换、2 明确选择、3 脱离、4 销毁；延迟原因：1 Excel 编辑、2 窗口忙。

绘制采样区分实际选中与悬停数量，每栏至多每 250 ms 一次；状态快照至多每秒一次、最多 32 个视图；布局延迟至多每 500 ms 一次。抑制与截断计数标明限制。记录能够补充排查证据，不能保证每次故障都留有完整根因。

0.2.0 提供默认开启的结构化操作日志。发生问题后尽快打开 **openOfficetab → 设置与恢复 → 管理中心 → 诊断与修复 → 导出诊断与日志**，将导出的 JSON 附在 issue 中，同时说明触发动作、发生时间、预期和实际结果。日志只保存在本机，不自动上传。

日志关联以下信息：

- 插件版本、宿主类型、位数、Office 主版本/构建号及视图 DPI。
- Office 事件编号、新建/打开/保存/关闭请求、标签切换、分组及设置操作。
- 会话内视图编号、窗口编号、原生激活、拖动开始/结束位置、COM 活动视图与原生窗口是否一致。
- 安装、修复、更新等管理中心操作的开始/结束、耗时及错误码。

默认不采集文档名称、文件路径、正文、单元格内容、公式、账号、网络地址、令牌或 Office 异常描述。窗口编号和标签编号仅用于关联同一运行过程。`GetState` 是包含文档身份的开发接口，不属于公开诊断附件。

原生记录位于 `%LOCALAPPDATA%\openOfficetab\logs`。每条为 schema 1 JSONL，含 UTC 毫秒时间、单调时钟、进程/线程、运行编号和序号。宿主编号 0/1/2 表示 Word/Excel/PowerPoint，3 表示管理服务；编号不能跨运行识别具体文档。操作开始不代表完成，关闭请求也不代表用户已接受保存提示。

原生窗口回调仅写内存缓冲（64 KiB）；正常空闲时批量写盘，正常断开时排空。近期内存时间线保留约 128 KiB。磁盘单文件不超过 1 MiB，每进程保留当前文件和三个轮转文件；启动时清理七天前记录并将可清理旧记录控制在约 32 MiB，正在使用的文件不强制删除。管理服务同样保留四个最多 1 MiB 的文件。拥塞或写入失败不阻塞插件，丢弃数量会记录；突然崩溃可能丢失最后一个尚未写入的缓冲。

管理中心最多读取最近八个结构化文件、导出最近 4096 条事件，标明截断、跳过或损坏记录。导出再次按字段白名单过滤，不附加旧 `runtime.log`、设置 INI、文件历史、截图或文档。界面预览只显示末尾 30 条，导出包含完整受限时间线。原生“导出脱敏诊断”入口导出当前宿主快照与近期内存时间线；跨宿主调查推荐使用管理中心。

测试样本由 `tests/generate-stress-fixtures.py` 生成到隔离的 `artifacts/stress-fixtures-v1`，可重复用于大工作簿、多工作表和含图长文档回归，不包含用户原件。离线日志测试不能替代真实 Office 运行和问题现场复现。
