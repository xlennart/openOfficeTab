# 单窗口观感与拖动露窗调查

日期：2026-10-17。状态：v0.1.6 已完成原生验证，使用者确认基本可用并批准发布；专项场景的限制见验证记录。

## 当前问题

用户截图中，同一 Word 标签组的两个原生文档窗口同时可见。此前将其他窗口的位置、尺寸同步推迟到拖动结束，虽然避开了已发现的刷新循环，却让后台窗口在拖动过程中暴露。即使松开后矩形完全一致，也不能据此认定已达到“一个窗口里的多个标签”的体验。Excel、Word、PowerPoint 共用这条协调路径，必须一并处理。

刷新循环、宿主尺寸回调重入问题的修复予以保留。早期仅在松手后对齐的预览未达到目标，后续增加拖动前的显示遮蔽；单次 SetWindowPos 或原生消息序列通过，不等于真实鼠标拖动通过。

## 对标样本的已核对证据

来自此前保存的 OfficeTab x64 样本静态反编译，本轮重新读取了原始函数结果，不是对当前安装版竞品进行实机观察。函数地址只对应该样本。

| 宿主 | RearrangeAppWindow |
| --- | --- |
| Word | `0x1095610` |
| Excel | `0x1059690` |
| PowerPoint | `0x1012d80` |

三套普通窗口排列路径都包含以下操作：

1. 检查活动窗口、可见性和重入状态。
2. 暂时把活动窗口设到 TOPMOST 层级。
3. 对其他成员调用 `0x10c0510(hwnd, 0)`，随后调用 `LockWindowUpdate`。
4. 用 MoveWindow / SetWindowPlacement 对齐位置、尺寸和还原状态，必要时以不激活方式显示。
5. 调用 `0x10c0510(hwnd, 255)`，最后将活动窗口改回 NOTOPMOST 并解除更新锁。

辅助函数 `0x10c0510` 明确将扩展样式加上 `WS_EX_LAYERED`，再以 `(hwnd, 0, alpha, 2)` 的参数形态调用动态入口。这与 SetLayeredWindowAttributes + LWA_ALPHA 的接口吻合；动态目标地址尚未完整追溯，因此透明度控制仍是高度支持的解释，不能写成动态绑定已确认。更新锁本身也不等于隐藏窗口。

已分析的排列链仍然保留多个 Office 顶层窗口，没有证据表明它把文档顶层窗口 SetParent 到统一 MDI 容器。任务栏入口另由 AddTab / DeleteTab 协调，不能用“任务栏只有一个入口”证明屏幕上只有一个窗口。

- 本机 `ghidra-window-core` 分析结果：`0x1095610.json`、`0x1059690.json`、`0x1012d80.json`
- 本机 `ghidra-critical-core` 分析结果：`0x10c0510.json`

## 修正方向

继续保留 Office 原生文档窗口，但为标签组增加独立的显示状态管理，而不再仅让可见窗口追赶坐标：

- 从拖动开始到结束，同组非当前窗口不应暴露；显示控制必须早于第一次几何变化。
- 拖动中只由当前窗口参与可见交互，结束时先完成后台窗口的位置、尺寸同步，再恢复适当的显示状态和层级；切换标签也须明确转移可见交互窗口。
- 几何同步继续合并通知、避免 Office 布局回调中的重入，不恢复无限 REFRESH 循环。
- 先验证可恢复的短期显示遮蔽方案；不得直接把 Workbook.Window.Visible 关闭而令现有枚举将其误判为消失。
- 保存并仅恢复本插件修改的层级、分层样式和透明度。模态提示、拖动取消、独立窗口、退出单窗口模式及禁用插件均须有恢复分支。避免照搬全局更新锁和长期强制置顶。

这是一条需要验证的自主实现方案，不是已证明对标项目在所有拖动阶段都执行同一策略。动态入口、调用触发点及恢复路径仍应继续核对。

## 完成条件

三款 Office 分别用两个及多个标签，实际连续大幅拖动、调整各边缘、最大化 / 还原、最小化 / 恢复、分屏后切换。验收要同时满足：不露出同组其他窗口、不挂起、不闪出后台窗口、不抢模态焦点；取消拖动和禁用插件可以恢复。自动原生消息测试只覆盖逻辑和响应性，最终观感由用户手动体验确认后再发布和回复 issue。

## 本地实现记录

2026-10-17 的 0.1.6加入了临时分层透明遮蔽：在移动 / 调整大小开始及首个位置变化前遮蔽同组兄弟窗口，保留 Office 的可见属性；结束后先同步几何、安排到当前窗口后方，再恢复原有分层位、色键和透明度。取消、窗口销毁、移出分组、恢复与插件断开均释放自有遮蔽；窗口属性令牌用于防止 HWND 复用后恢复到错误窗口。无法读取原分层属性的窗口不强行修改。没有照搬竞品的全局更新锁或临时 TOPMOST。

补充保留最小化事件优先级，以及 PowerPoint 活动文档恢复。最终构建及运行验证范围见 [验证记录](validation.md)。使用者已手动体验并确认基本可用；多显示器、不同 DPI、放映与第三方加载项组合仍需专项验证。遮蔽 API 返回成功本身不能代替观感验收。
